## 1. В карточке исполнителя нет числа съёмок

Правка №3: «Не отображается в цифрах опыт и количество съёмок».

`years_experience` в списке есть, и число опыта мы уже выводим. Счётчиков
в списке нет — они только в анкете:

```
GET /site/performers?specialty=photographer
  items[] → { years_experience: 9, shoots_count: null, cases_count: null, brands_count: null }

GET /site/performers/{id}
  profile → { years_experience: 9, shoots_count: 31, brands_count: 12, projects_count: 20 }
```

### Что добавить

В **элементы списка** `GET /site/performers` — те же поля, что уже есть в `profile`:

```json
{
  "years_experience": 9,
  "shoots_count": 31,
  "cases_count": 12
}
```

### Как мы это читаем

| Поле | Куда идёт | Где видно |
|---|---|---|
| `years_experience` | чип «9 лет опыта» | карточка фотографа (Figma 93:7245), видеографа (138:8181) |
| `shoots_count` | чип «31 съёмок» | карточка фотографа |
| `cases_count` | чип «12 кейсов» | карточка видеографа |

`cases_count` можно не заводить отдельно — читаем `cases_count ?? brands_count`,
подойдёт любое из двух. Если поля нет или `null`, чип просто не рисуется —
как сейчас.

## 2. Не видно, в каком агентстве состоит исполнитель

Правка №7: «Модели, фотографы, видеографы, которые есть в каких-либо
агентствах, не отображаются в их карточке».

Со стороны агентства всё есть — `GET /site/agencies/{id}` возвращает
`performers[]`, страница агентства их показывает. Обратной связи нет:

```
GET /site/agencies/u-b0c314c57273
  user.agency_name = "Star Agency"
  performers[0]    = { id: "1c1bc731-…", first_name: "Анна", last_name: "Моделева" }

GET /site/performers/1c1bc731-…          ← та же Анна
  user.agency_name = null
  agency / agency_id / agency_slug — полей нет вообще

GET /site/performers?specialty=model     ← и в списке тоже
  items[].agency_name = null
```

### Что добавить

В `GET /site/performers/{id}` — вложенный блок на верхнем уровне ответа
(рядом с `user`, `profile`, `media`):

```json
{
  "agency": {
    "id": "b0c314c5-7273-48f1-bc59-cf18c8d5139c",
    "slug": "u-b0c314c57273",
    "name": "Star Agency",
    "logo_url": "https://admin.agunastroy.ru/uploads/demo/p-agency.jpg"
  }
}
```

Если исполнитель ни в каком агентстве не состоит — `"agency": null`
(или просто не присылать ключ).

### Как мы это читаем

| Поле | Куда идёт |
|---|---|
| `agency.name` | подпись на плашке |
| `agency.logo_url` | логотип 37×37 слева |
| `agency.slug` (или `id`) | ссылка `/agencies/{slug}` |

Плашка — Figma 345:19391, встаёт справа от «Пригласить в проект» на анкете
модели, фотографа и видеографа. Компонент уже написан
(`components/shared/detail/agency-badge.jsx`), при `agency: null` не рисуется.

**Мы принимаем три формы**, достаточно любой — выбирайте, что вам проще:

```
1. agency: { id, slug, name, logo_url }              ← предпочтительно
2. agency: { id, slug, agency_name, logo_url }
3. плоские поля: agency_id, agency_slug, agency_name, agency_logo_url
```

Плоские поля читаем и с верхнего уровня, и из `user`.

Заодно: в `performers[]` у агентства `slug: null`, ссылки строим по UUID.
Если проставите слаг — адреса станут читаемыми.

## 3. Нет чата техподдержки

Правка №12: «нет чата техподдержки в сообщениях на аккаунтах пользователей».

Проверили — такой сущности нет:

```
GET  /site/support        → 404
GET  /customer/support    → 404
GET  /support/chat        → 404
POST /customer/chats      → 422 (требует peer_id — нужен собеседник)
GET  /customer/chats      → 200, items[].kind = "direct" (других видов нет)
```

### Что добавить

Одну ручку — системного пользователя поддержки:

```
GET /site/support
Authorization: Bearer <любая роль>
```

```json
{
  "user_id": "00000000-0000-0000-0000-000000000001",
  "name": "Поддержка",
  "logo_url": "https://admin.agunastroy.ru/uploads/support.png"
}
```

Дальше нам ничего особенного не нужно — открываем обычный диалог тем же
способом, что и «Написать» в профиле:

```
POST /customer/chats   { "peer_id": "<user_id из /site/support>" }
POST /performer/chats  { "peer_id": … }
POST /agency/chats     { "peer_id": … }
```

То есть поддержка должна быть обычным пользователем, с которым разрешено
открыть чат любой роли.

### Как мы это читаем

| Поле | Куда идёт |
|---|---|
| `user_id` | `peer_id` при открытии диалога |
| `name` | подпись на кнопке (если пусто — «Поддержка») |
| `logo_url` | аватар в списке чатов |

Кнопка стоит в шапке раздела «Сообщения» у всех ролей. Пока ручка отдаёт
`404`, кнопка не рисуется — экран выглядит как сейчас. Как только ответ
станет `200`, кнопка появится сама.

Если удобнее не заводить системного пользователя — подойдёт и вариант
`POST /site/chats/support` без тела, который создаёт (или возвращает
существующий) диалог и отдаёт `{ "conversation_id": … }`. Тогда скажите —
поменяем один вызов.

Хорошо бы, чтобы такие диалоги были видны админу в `GET /admin/chats`
(сейчас там пусто) — иначе отвечать на обращения будет негде.

## Что закрыли у себя (для контекста)

Правки 1, 2, 4, 5, 6, 8, 9, 10, 11 и фронтовая часть 3 — сделаны и проверены
в браузере, изменений на бэкенде для них не нужно. Два места, где помогла
ваша сторона:

- у площадки владелец ведёт на `GET /site/customers/{id}` — раньше мы стучались
  в несуществующий `/persons/{slug}` и страница отдавала «Профиль не найден».
  Ручка принимает только UUID (со слагом `422`), ссылку строим по `owner.id`;
- в списках админки статус приходит как `blocked` — мы ошибочно переводили его
  в `rejected`, из-за чего в таблице стоял «—» и не было пункта «Разблокировать».
